# シエル × Obsidian 連携拡張構想

## 概要

シエルとObsidianを連携させることで、Obsidian Vaultを単なるノート置き場ではなく、**シエルが参照・整理・更新できる外部知識ベース**として利用できる。

現在はすでに、

- Obsidian Vault内の記事検索
    
- 質問内容に関連するノートの取得
    
- 複数ノートを参照した情報の要約
    

が実装されている。

例えば、

> 「ノートにα7Ⅴの情報ある？」

と質問すると、シエルがVault内の関連ノートを検索し、その内容をもとにα7Ⅴについて回答できる。

今後はこの「読む」機能を発展させ、**書く・整理する・関連付ける・検証する**機能までシエルに担当させることで、Obsidianをシエルの「外部脳」として利用できる。

---

# 現在の構成

基本構造は以下。

```
ユーザー
  ↓
シエル
  ↓
質問・意図解析
  ↓
Obsidian検索
  ↓
関連ノート取得
  ↓
ローカルLLM
  ↓
要約・回答
```

例：

```
「α7Ⅴについてノートに情報ある？」
        ↓
Vault検索
        ↓
[[SONY α7Ⅴ]]
[[カメラ設定]]
[[撮影機能]]
        ↓
必要な部分を抽出
        ↓
ローカルLLMが統合
        ↓
回答
```

この構造を双方向化するのが今後の拡張方針となる。

---

# 1. 会話からObsidianへ直接記録

現在の、

```
Obsidian
   ↓
シエル
```

という一方向の情報取得に、

```
シエル
   ↓
Obsidian
```

を追加する。

例えば、

> 「シエル、α7Ⅴのプリ撮影が便利だったってメモして」

と伝える。

シエルが対象ノートを検索し、

```
# SONY α7Ⅴ

## 使用感

- プリ撮影機能が便利だった。
```

のように適切な位置へ追記する。

これにより、

```
会話
↓
情報抽出
↓
既存ノート検索
↓
追記場所判定
↓
Obsidian更新
```

という流れが成立する。

Obsidianを直接操作する必要が減り、**自然言語そのものをVaultへの入力インターフェースとして利用できる。**

---

# 2. 会話から新規ノートを生成

既存ノートへの追記だけでなく、新しい知識を独立したノートとして作成する。

例えば、

> 「今日解決したComfyUIのIPAdapterエラーを記事にして」

と指示すると、

```
# ComfyUI IPAdapter エラー対処

## 症状

IPAdapter Unified Loaderで処理が停止する。

## 原因

...

## 解決方法

...

## 関連ノート

- [[ComfyUI]]
- [[SDXL]]
- [[IPAdapter]]
```

のような記事を生成してVaultへ保存する。

シエルとのトラブルシューティング結果を、そのまま知識として蓄積できる。

---

# 3. 会話終了時の「保存候補」抽出

すべての会話を保存するとVaultに不要な情報が大量に増える。

そのため、自動保存ではなく、

> 「今回の会話には保存価値のある情報が3件あります。」

という形で保存候補を抽出する。

例：

```
保存候補

1. IPAdapter 403エラーの原因
2. VRAM解放方法
3. SDXL Reference構成
```

ユーザーが承認したものだけ記事化する。

基本フロー：

```
会話
↓
Knowledge Extractor
↓
保存価値判定
↓
候補提示
↓
ユーザー承認
↓
Obsidian保存
```

この方式ならVaultの情報密度を維持しやすい。

---

# 4. 「前にも調べた？」検索

Vaultをシエルの過去知識として利用する。

例えば、

> 「トナカイの目の話って前にも調べた？」

と聞く。

シエルはタイトルの完全一致だけではなく、ノート本文やEmbedding検索などを利用して類似情報を検索する。

結果として、

```
関連ノートを1件検出。

[[トナカイの目が夏と冬で変化する理由]]

内容：
夏は金色、冬は青色に変化する現象についてまとめています。
```

のように回答する。

これにより、

- 同じ内容を何度も調べる
    
- 似た記事を何個も作る
    
- 過去に得た知識を忘れる
    

といった問題を抑えられる。

---

# 5. 関連ノートの自動探索

検索対象そのものだけでなく、周辺知識まで探索する。

例えば、

> 「α7Ⅴについて教えて」

と聞いた場合、

```
直接関連
├─ [[SONY α7Ⅴ]]
├─ [[α7Ⅴ カメラ設定]]
└─ [[α7Ⅴ プリ撮影]]

関連ノート
├─ [[SEL35F18F]]
├─ [[SIGMA 85mm F1.4 DG DN]]
├─ [[Godox AD100Pro II]]
└─ [[SONY Eマウント]]
```

のように知識グラフを辿る。

検索方式としては、

```
質問
↓
直接検索
↓
関連ノート取得
↓
[[内部リンク]]解析
↓
バックリンク解析
↓
必要なノートだけ追加取得
↓
LLMへ投入
```

という方法が考えられる。

単純な全文検索よりも、Obsidianのリンク構造を有効活用できる。

---

# 6. 関連ノートの自動リンク

新しいノートを作成した際、Vault内から関連ノートを探す。

例えば、

```
# SONY α7Ⅴ プリ撮影
```

という記事を作った場合、

```
## 関連ノート

- [[SONY α7Ⅴ]]
- [[SONY カメラ設定]]
- [[動体撮影]]
```

などをシエルが候補として提示する。

同時に既存の `[[SONY α7Ⅴ]]` 側にも、

```
- [[SONY α7Ⅴ プリ撮影]]
```

を追加できる。

これによってVault内の知識同士が自動的につながっていく。

---

# 7. 重複ノート検出

新規記事を作る前に、類似ノートが存在しないか確認する。

例えば、

```
新規ノート候補：
「SONY α7Ⅴ プリ撮影機能」
```

に対して、

```
類似度 94%
[[α7Ⅴ プリ撮影について]]
```

が存在した場合、

> 「類似記事があります。新規作成ではなく既存記事へ統合できます。」

と通知する。

処理としては、

```
新規内容
↓
Embedding生成
↓
Vaultベクトル検索
↓
類似度判定
↓
高類似ノート検出
↓
新規作成 / 追記 / 統合
```

となる。

ノート数が増えるほど効果が大きくなる機能。

---

# 8. ノート間の矛盾検出

複数ノートに同じ対象について異なる情報が記録されている場合、それを検出する。

例：

```
ノートA
「最大30fps」

ノートB
「最大10fps」
```

この場合、

```
矛盾候補を検出

[[ノートA]]
最大30fps

[[ノートB]]
最大10fps
```

として提示する。

ただし、数値が異なるだけで即座に「間違い」と判定してはいけない。

例えば、

- 撮影モードが違う
    
- RAW/JPEG条件が違う
    
- ファームウェアが違う
    
- 世代が違う
    
- 記事作成時期が違う
    

可能性がある。

そのため、

```
矛盾候補検出
↓
関連コンテキスト比較
↓
本当に矛盾している可能性が高い場合のみ提示
```

という設計が適切。

---

# 9. 古い情報の検出

Frontmatterなどに更新日時を持たせる。

```
---
created: 2026-01-10
updated: 2026-01-15
---
```

これを利用して、

```
LM Studio
最終更新：2025-12-03

ComfyUI
最終更新：2026-01-20
```

など、長期間更新されていない記事を検出する。

ただし、

> 「古い記事 = 間違った記事」

ではない。

そのためシエルは、

```
古い
```

ではなく、

```
再確認候補
```

として扱う方が適切。

# 10. Web検索との組み合わせ

ローカルLLM自体には通常、現在のWebを検索する能力はない。

ただし、

```
シエル
↓
Web Search Tool
↓
検索サービス
↓
検索結果
↓
ローカルLLM
```

という外部ツール方式にすればWeb検索を追加できる。

例えば、

> 「このObsidianの記事、今も正しい？」

という質問なら、

```
              ┌─ Obsidian検索
ユーザー ────┤
              └─ Web検索
                    ↓
           ローカルLLM
                    ↓
              情報比較
```

となる。

重要なのは、**LLM自身が検索するわけではない**という点。

Web検索担当とLLMを分離する。

---

## Web検索の利用例

例えば、

> 「α7Ⅴのノートが最新情報と一致しているか確認して」

と指示する。

```
Obsidian
↓
現在保存されているα7Ⅴ情報

+

Web Search Tool
↓
現在公開されている情報

↓

LLM
↓
差分抽出
```

結果：

```
Vaultの記事には○○と記載されています。

現在取得した情報では○○となっています。

更新候補：
- ○○
- ○○
```

この結果から直接記事を書き換えるのではなく、更新候補として提示する。

---

# 11. Web検索エンジンの候補

Web検索Toolには複数の実装方法がある。

## Tavily

AIエージェントやLLMから利用することを前提とした検索API。

検索結果をLLMへ渡しやすい形式で取得できるため、比較的実装しやすい。

構成：

```
シエル
↓
Tavily API
↓
検索結果
↓
ローカルLLM
```

## SearXNG

自分のPCやサーバーで動かせるメタ検索システム。

HTTP API経由で検索でき、設定によってJSON形式の検索結果を取得できる。

構成：

```
シエル
↓
localhost
↓
SearXNG
↓
Web検索
↓
JSON
↓
ローカルLLM
```

シエルをローカル中心で構築する場合はこちらも候補になる。

# 12. Vault限定回答モード

シエルの一般知識とObsidianの情報が混ざると、

> 「その情報はVaultに書いてあったのか、LLMが知っていたのか」

が分からなくなる。

そこで回答モードを分ける。

```
Vault Only
Web Only
Vault + Web
通常LLM
```

### Vault Only

> 「Vaultだけ参照してα7Ⅴについて教えて」

```
参照可能：
Obsidian

使用禁止：
Web検索
LLM内部知識による補完
```

### Vault + Web

> 「ノートの内容が現在も正しいか確認して」

```
Obsidian
+
Web検索
↓
比較
```

### 通常LLM

一般的な質問では通常のLLM知識も使用する。

# 13. 回答の参照元表示

RAGで特に重要なのが出典管理。

シエルがObsidianを参照して回答した場合、

```
α7Ⅴには○○という機能があります。

参照：
[[SONY α7Ⅴ]]
[[α7Ⅴ カメラ設定]]
```

のように、利用したノートを表示できるようにする。

これにより、

- 回答根拠を確認できる
    
- 元記事へすぐ移動できる
    
- 誤情報発生時に原因を追跡できる
    
- ノート自体を修正できる
    

という利点がある。

# 書き込み権限の設計

Obsidianへ書き込みできるようになると、誤操作対策が重要になる。

推奨する権限レベル：

|操作|権限|
|---|---|
|ノート検索|自動実行|
|ノート読み込み|自動実行|
|関連ノート検索|自動実行|
|新規ノート作成|確認後実行|
|既存ノート追記|確認後実行|
|Frontmatter変更|確認後実行|
|MOC更新|確認後実行|
|ファイル移動|確認後実行|
|複数ノート統合|必ず確認|
|ノート削除|必ず確認|

基本思想は、

```
READ
→ 自由

ANALYZE
→ 自由

WRITE
→ 原則確認

DELETE
→ 必ず確認
```

とする。

# 最終的なシエル × Obsidianの役割

現在：

```
Obsidian
↓
検索
↓
シエル
↓
回答
```

拡張後：

```
                  ┌─ 検索
                  ├─ 要約
                  ├─ 関連付け
                  ├─ 重複検出
                  ├─ 矛盾検出
                  ├─ 更新候補検出
                  ├─ 記事生成
シエル ⇄ Obsidian ├─ 追記
                  ├─ Frontmatter管理
                  ├─ MOC管理
                  ├─ Inbox整理
                  └─ Web情報との比較
```

つまり、Obsidianを単に、

**「シエルが検索できるノート」**

として利用するのではなく、

**「シエルが読み書き・整理・検証できる永続的な外部知識ベース」**

へ発展させる。

最終的には、

> 「これ前に調べた？」

> 「この情報まだ正しい？」

> 「今日分かったことをノートにして」

> 「似た記事ある？」

> 「この話を既存の記事に追加して」

> 「AI関連の記事を整理して」

といった操作をすべて自然言語で実行できる状態が、シエル × Obsidian連携の完成形となる。

```
     ↓
シエル
     ↓
知識抽出
     ↓
Obsidian
     ↓
整理・関連付け
     ↓
長期保存
     ↓
後日のシエルが再利用
     ↓
必要ならWebで再検証
     ↓
知識更新
```

この循環が成立すると、シエルとの会話で得た知識が蓄積され、その知識を将来のシエル自身が再利用できる。

そのため、Obsidianはシエルにとって単なる連携アプリではなく、**継続的に成長する外部記憶・知識データベース**として機能する。
