# シエルのビジュアル化・デスクトップ常駐アバター実装計画

> [!NOTE]
> **この手法で上手くいかなかった場合、[[シエルのデスクトップ常駐アバター化 - 代替案]]を使用する。**

## 目的

シエルをWindowsデスクトップ上に常駐する**軽量2Dアバター**としてビジュアル化する。

最終的には、単に立ち絵を表示するだけではなく、シエル本体の状態に応じて、

- 通常
    
- 笑顔
    
- 驚き
    
- 困り
    
- 眠そう
    
- 思考中
    
- 発話中
    
- 通知あり
    

などを視覚的に表現する。

重要なのは、**画像生成AIを常時動かすのではなく、事前に生成したPNG素材だけを常駐アプリ側で表示すること**。

これにより、デスクトップ常駐中のGPU負荷を最小限に抑える。

---

# 1. 採用する最終構成

シエルの用途では、以下の構成を採用する。

```
【素材制作時のみ】

シエル基準立ち絵
       ↓
CharacterVariationGenerator
       ↓
SAM3で顔領域をマスク
       ↓
SDXL Inpainting
       ↓
5種類の表情差分
       ↓
Photoshop
       ↓
位置・色・透過・サイズを統一
       ↓
PNG素材完成


【通常運用時】

シエル本体
   ↓
状態情報
   ↓
localhost WebSocket
   ↓
PySide6 アバターアプリ
   ↓
PNGを切り替えて表示
```

つまり、

**CharacterVariationGeneratorは表情素材を作るためだけに使用する。**

完成後の常駐アバターではSDXL・SAM3・ComfyUIなどを起動する必要はない。

---

# 2. なぜこの方式を採用するのか

## CharacterVariationGenerator

通常のImage-to-Imageでは画像全体が再生成されるため、表情を変えただけでも、

- 服の装飾
    
- ボタン
    
- 髪飾り
    
- 髪型
    
- 身体
    
- 背景
    

などが微妙に変化することがある。

CharacterVariationGeneratorでは、SAM3で対象領域をマスクし、その部分だけSDXL Inpaintingで再描画する。

元記事でも、**顔以外を保護しながらInpaintingすることで、服装やアクセサリーの一貫性を維持して表情だけ変更する**方式として説明されている。

シエルのアバターでは表情を高速に切り替えるため、「表情以外が動かない」ことが特に重要になる。

---

# 3. アバターは「上半身」を採用する

基本素材は**上半身立ち絵**とする。

```
頭
│
顔
│
肩
│
胸
│
腰より少し上
```

全身ではデスクトップ上で顔が小さくなり、表情が分かりにくい。

一方、顔だけではキャラクターとしての存在感が弱くなる。

そのため、

**上半身を基本表示**

とする。

将来的には、

```
通常
→ 上半身

省スペース
→ 顔だけ

会話モード
→ 上半身を少し拡大
```

と切り替えてもよい。

---

全体を以下の6フェーズに分ける。

# Phase 1：CharacterVariationGeneratorの導入

## 5. 専用環境として導入する

CharacterVariationGeneratorはComfyUIとは別アプリとして使用する。

そのため、

**ComfyUIのPython環境へ直接インストールしない。**

依存関係の競合を避けるため、専用のPython仮想環境を作成する。

リポジトリの現在の`requirements.txt`にはPyTorch、Diffusers、Transformers、Gradio、Ultralytics、Real-ESRGANなどが含まれているため、既存のAI環境と分離しておく方が安全である。

# 6. リポジトリを取得する

PowerShellまたはコマンドプロンプトで任意の設置フォルダへ移動する。

```

cd CharacterVariationGenerator
```

公式READMEでもこの方法が案内されている。

# 11. SDXLモデルを用意する

表情生成にはSDXL Checkpointを使用する。

形式：

```
.safetensors
```

公式READMEではアニメ系SDXLモデルが推奨されている。

既に使用実績のあるアニメ系SDXLモデルがある場合は、まずそれを試す。

モデルは例えば、

```
CharacterVariationGenerator/
└─ assets/
   └─ models/
      └─ sdxl/
         └─ model.safetensors
```

へ配置する。

ただし、既存のSDXLモデルフォルダをそのまま参照させてもよい。

# 12. SDXLモデルフォルダを登録する

```

```

```

  model_directories:
```

へモデルフォルダを登録する。

公式READMEではデフォルトとして、

```

```

が想定されている。

例えば外部フォルダを使う場合：

```
expression_editor:
  model_directories:
    - D:/AI/Models/SDXL
```

とする。

# Phase 2：シエルの基準画像を作る

## 14. 基準画像を1枚に固定する

ここが非常に重要。

まず、

**シエルの正式な基準上半身画像を1枚だけ決定する。**

例えば、

```
ciel_master.png
```

とする。

条件：

- 上半身
    
- 髪型完成済み
    
- 服装完成済み
    
- 顔完成済み
    
- 構図完成済み
    
- カメラ角度固定
    
- 照明固定
    
- キャラクター位置固定
    

一度基準画像を決めた後は、これをすべての表情生成の元にする。

---

# 15. 表情差分はすべて同じ画像から作る

必ず、

```
          ┌→ Smile
          │
Neutral ──┼→ Surprised
          │
          ├→ Troubled
          │
          └→ Sleepy
```

とする。

以下のような方法にはしない。

```
Neutral
 ↓
Smile
 ↓
Surprised
 ↓
Troubled
```

編集結果から次の表情を作ると、少しずつ顔が変化していく可能性がある。

# Phase 3：CharacterVariationGeneratorで表情を作る

## 16. シエル画像をアップロードする

WebUIの、

```
Upload Character Image
```

から、

```
ciel_master.png
```

を読み込む。

---

# 17. SAM3でマスクを生成する

```
Generate Mask
```

を実行する。

SAM3が対象領域を検出し、マスクを生成する。生成後はプレビューでマスク範囲を確認できる。

---

# 18. マスク範囲を確認する

シエル用途では、

**可能な限り顔の内側だけを変更する**

のが理想。

変更したい部分：

```
眉
目
目元
鼻周辺
頬
口
```

なるべく変更させたくない部分：

```
髪の外周
頭部外周
耳
顎の輪郭
首
肩
服
身体
背景
```

特に髪型と身体が固定されていれば、表情切り替え時の位置ズレが大幅に減る。

---

# 19. ベースプロンプト

表情生成では顔関連だけを指定する。

例：

```
detailed eyes, pupils, eyebrows, nose, mouth,
consistent face shape, clean anime face
```

---

# 20. ネガティブプロンプト

例：

```
deformed, distorted face, asymmetrical eyes,
bad eyes, bad mouth, blurry, malformed face
```

過剰に長くする必要はない。

---

# 21. 最初に作る5種類

初期版では以下の5種類だけ作る。

|ID|表情|用途|
|---|---|---|
|`neutral`|通常|待機|
|`smile`|笑顔|通常会話・成功|
|`surprised`|驚き|想定外の情報|
|`troubled`|困り|エラー|
|`sleepy`|眠そう|深夜・休止|

---

# 22. 表情プロンプト

## Neutral

基準画像そのものを使用するため、原則として生成しない。

```
neutral expression
```

は必要な場合のみ使用する。

---

## Smile

```
gentle smile, relaxed eyebrows, soft eyes,
closed mouth smile
```

大きく口を開けない。

後から口パクを追加しやすくするため、

**閉じ口の笑顔**

を基本とする。

---

## Surprised

```
mildly surprised expression,
slightly raised eyebrows,
slightly widened eyes,
slightly open mouth
```

極端な驚き顔にはしない。

---

## Troubled

```
slightly troubled expression,
worried eyebrows,
soft worried eyes,
subtle worried mouth
```

---

## Sleepy

```
sleepy expression,
half-closed eyes,
relaxed eyebrows,
slightly tired expression
```

---

# 23. Denoising Strength

CharacterVariationGeneratorでは、Denoising Strengthを上げるほど元画像から離れ、表情プロンプトの影響が強くなる。

シエル用途では、

```
0.35～0.50
```

付近から開始する。

### 表情が弱い場合

```
Denoising Strength
↑
```

### 顔そのものが変わる場合

```
Denoising Strength
↓
```

まずは低めを優先する。

---

# 24. Guidance Scale

初期値の候補：

```
7.0～8.0
```

表情プロンプトに従わない場合だけ少し上げる。

---

# 25. バッチ生成する

表情プロンプトを設定したら、

```
Generate Batch
```

を実行する。

CharacterVariationGeneratorは複数の表情差分をバッチ生成でき、生成結果はギャラリー表示されるほか、

```
outputs/images/
```

へ保存される。

---

# 26. 1種類につき複数候補を作る

各表情について、

```
2～4候補
```

程度生成する。

評価ポイント：

- シエル本人に見える
    
- 目の高さが変化していない
    
- 鼻の位置が変化していない
    
- 顔の大きさが変わっていない
    
- 髪型が変わっていない
    
- 服が変化していない
    
- 背景が変化していない
    

最も自然な1枚だけ採用する。

---

# Phase 4：Photoshopで最終素材化

## 27. CharacterVariationGeneratorの出力をそのまま使わない

AI生成結果には数ピクセル程度の差が残る可能性がある。

デスクトップアバターでは、

```
Neutral
↓
Smile
↓
Neutral
```

と高速に切り替えるため、わずかなズレでも顔が「ガクッ」と動いて見える。

そのためPhotoshopで最終調整する。

---

# 28. マスターPSDを作る

例：

```
Ciel_Avatar_Master.psd
```

レイヤー構成：

```
Ciel_Avatar_Master.psd

├─ BASE
│  └─ neutral
│
├─ EXPRESSIONS
│  ├─ smile
│  ├─ surprised
│  ├─ troubled
│  └─ sleepy
│
└─ GUIDE
   └─ alignment
```

Neutral画像は絶対に動かさない。

---

# 29. 表情を位置合わせする

各生成画像をNeutralの上に配置する。

一時的に不透明度を50%程度へ下げ、

```
目
鼻
顎
```

を基準に合わせる。

必要ならPhotoshopの描画モード、

```
差の絶対値 / Difference
```

を使用する。

輪郭が最も一致する場所へ微調整する。

---

# 30. 変更範囲を顔だけに限定する

AI生成画像全体を使用するのではなく、

**表情に必要な部分だけレイヤーマスクで表示する**

方法が安定する。

使用：

```
眉
目
頬
口
```

元画像を維持：

```
髪
輪郭
首
肩
服
身体
背景
```

これにより表情切り替え時のズレを最小化できる。

---

# 31. 色を統一する

必要に応じて、

```
トーンカーブ
レベル補正
色相・彩度
```

を使用する。

確認する部分：

```
肌色
白目
影
頬
```

5枚を切り替えたとき、

**表情以外の色が変わらない状態**

を目標とする。

---

# 32. 背景を透明化する

デスクトップ常駐アバターでは背景を透明にする。

最終PNGは、

```
RGBA
背景透明
```

で保存する。

---

# 33. すべて同一キャンバスにする

例えば、

```
1600 × 2200
```

など。

重要なのはサイズそのものではなく、

```
全画像が完全に同じ解像度
全画像が完全に同じ位置
```

であること。

---

# 34. 初期表情素材を書き出す

```
avatar/
└─ expressions/
   ├─ neutral.png
   ├─ smile.png
   ├─ surprised.png
   ├─ troubled.png
   └─ sleepy.png
```

---

# 35. 表情切り替えテストを行う

Photoshop上で高速に、

```
neutral
smile
surprised
troubled
sleepy
```

を切り替える。

確認：

```
髪が動かない
肩が動かない
服が動かない
頭が動かない
鼻が移動しない
```

**表情だけが変化して見えれば完成。**

# Phase 5：まず最小構成の常駐アバターを作る

## 36. 最初から口パクや瞬きを実装しない

最初の完成ラインは、

```
透明ウィンドウ
+
上半身PNG表示
+
5表情切り替え
```

だけにする。

この段階で実際に数日使用し、

- 邪魔にならないか
    
- サイズは適切か
    
- 表情が見えるか
    
- 常時表示して問題ないか
    

を確認する。

---

# 37. 常駐アプリにはPySide6を使用する

推奨構成：

```
Python
+
PySide6 / Qt
```

PySide6を採用する理由：

- 透過ウィンドウ
    
- 枠なし表示
    
- Always On Top
    
- PNG透過
    
- ドラッグ移動
    
- クリック透過
    
- システムトレイ
    
- タイマー
    
- WebSocket
    

などを実装しやすい。

---

# 38. 常駐アプリの基本機能

初期版では以下のみ実装する。

```
背景透明
ウィンドウ枠なし
タスクバー非表示
ドラッグ移動
画面端に常駐
表情PNG変更
終了メニュー
```

---

# 39. デスクトップ上の表示位置

初期値として、

```
画面右下
```

を想定する。

ただしドラッグで自由に移動可能にする。

終了時には座標を保存し、次回起動時に同じ位置へ復元する。

---

# 40. 表示サイズ

27インチWQHD環境であれば、最初は高さ、

```
400～600px
```

程度から試す。

元画像そのものは大きくてもよい。

表示時に縮小する。

---

# 41. 常時60fpsで描画しない

PNGアバターでは常時描画する必要がない。

基本：

```
待機
→ 完全静止

表情変更
→ その瞬間だけ画像変更
```

とする。

そのため、待機中のGPU負荷は非常に小さくできる。

---

# Phase 6：シエル本体と連携する

## 42. シエル本体とアバターは別プロセスにする

構造：

```
ciel_core.exe / Python
       ↓
localhost
       ↓
ciel_avatar.exe / Python
```

アバター側が落ちてもシエル本体は動作する。

シエル本体が再起動してもアバターは独立して動作できる。

この分離が重要。

---

# 43. WebSocketで通信する

リアルタイム状態通知には、

```
localhost WebSocket
```

を使用する。

例えばシエルから、

```
{
  "emotion": "smile"
}
```

を送信する。

アバター側：

```
emotion = smile
↓
smile.png
```

へ変更する。

---

# 44. 使用する表情IDを固定する

シエルから自由な文章を送るのではなく、

```
neutral
smile
surprised
troubled
sleepy
```

の5種類だけ許可する。

例えば、

```
{
  "emotion": "troubled"
}
```

という形式。

これにより制御が安定する。

---

# 45. 表情変更ルール

初期設定：

|シエルの状態|表情|
|---|---|
|待機|`neutral`|
|通常会話|`neutral`|
|良い結果|`smile`|
|意外な結果|`surprised`|
|エラー|`troubled`|
|処理失敗|`troubled`|
|深夜・休止状態|`sleepy`|

---

# 46. LLMだけに表情を決めさせない

表情制御は、

```
システム状態
+
会話状態
+
必要に応じてLLM判定
```

の組み合わせにする。

例：

```
エラー発生
→ 強制 troubled

深夜＋待機
→ sleepy

正常処理完了
→ smile

通常
→ neutral
```

明確なシステムイベントはLLMを通さず決定する。

```

 ↓

 ↓
CLOSED
 ↓
HALF
 ↓
OPEN
```

短時間だけ切り替える。

# Phase 8：口パクを追加する

## 50. TTS再生と連動する

最終的にはTTS出力中だけ口パクする。

最低限、

```
mouth_closed
mouth_small
mouth_open
```

の3状態を使用する。

---

# 51. 音量ベースで口を制御する

高度なリップシンクは最初から必要ない。

TTS音声の音量を取得し、

```
無音
→ CLOSED

小さい音
→ SMALL

大きい音
→ OPEN
```

とするだけでも十分に口パクらしく見える。

---

# 52. 常時動かさない

発話中だけ、

```
10～20fps程度
```

で口を更新する。

発話終了後は完全静止。

これにより低負荷を維持する。

# Phase 9：「考え中」を視覚化する

## 53. Thinking状態

表情とは別に、

```
{
  "emotion": "neutral",
  "thinking": true
}
```

のような状態を持たせる。

例えば、

```
thinking = true
↓
小さな「…」エフェクト
```

を表示する。

必ずしも専用の「考え顔」を作る必要はない。

---

# 54. Obsidian検索と連動する

例：

```
マスター
「ノートにα7Ⅴの情報ある？」
        ↓
Obsidian検索開始
        ↓
thinking = true
        ↓
検索完了
        ↓
thinking = false
        ↓
```

# 61. 最終ゴールの考え方

シエルのビジュアル化の目的は、

**「AIキャラクターの絵をデスクトップに置くこと」**

ではない。

本質的な目的は、

**シエル内部の状態を視覚化すること**

である。

例えば、

```
待機している
考えている
検索している
話している
成功した
困っている
通知したい
眠そう
```

という状態を、画面を見るだけで理解できるようにする。

これにより、

```
音声AI
+
ローカルLLM
+
Obsidian
+
PC操作
+
スマートホーム
+
デスクトップアバター
```

が1つのパーソナルAIとして統合される。

---

# 62. 採用する最終方針

```
アバター形式
→ 2D上半身

表情素材生成
→ CharacterVariationGenerator

マスク
→ SAM3

表情生成
→ SDXL Inpainting

最終修正
→ Photoshop

初期表情
→ Neutral
→ Smile
→ Surprised
→ Troubled
→ Sleepy

常駐UI
→ PySide6

本体との通信
→ localhost WebSocket

待機時
→ 完全静止

発話
→ TTS音量による簡易口パク

瞬き

→ エフェクトレイヤー

```

この方式が、**軽さ・実装難度・キャラクター一貫性・拡張性のバランスが最も良い構成**となる。

# 64. 注意事項

CharacterVariationGeneratorは2026年10月4日時点で公開リポジトリのコミット数がまだ少なく、比較的新しいツールである。依存ライブラリも多いため、**ComfyUIなど既存環境とは必ず仮想環境を分けて運用する**方針が安全である。

また、CharacterVariationGeneratorはアバターを常時動かすソフトではない。

役割はあくまで、

```
表情素材を作る
```

ところまで。

完成後はCharacterVariationGenerator、SAM3、SDXLを起動せず、

```
PySide6
+
PNG
+
WebSocket
```

だけで常駐させる。

これがシエルを**低負荷で常時表示するための重要な設計方針**となる。
