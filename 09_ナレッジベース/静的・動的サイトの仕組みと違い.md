# 静的サイトと動的サイトの違いと仕組み

## 1. 概要

Webサイトは、ページの生成方法によって大きく**静的サイト（Static Website）**と**動的サイト（Dynamic Website）**に分類される。

最大の違いは、**Webページをあらかじめ用意して配信するか、アクセス時にサーバー側で生成するか**という点にある。

|比較項目|静的サイト|動的サイト|
|---|---|---|
|ページ生成|事前に生成|リクエストに応じて生成|
|サーバーの役割|保存済みファイルの配信|プログラムの実行・データ処理|
|データベース|基本的に不要|使用されることが多い|
|表示速度|高速にしやすい|処理内容やキャッシュ次第|
|サーバー負荷|比較的小さい|処理内容によって増加|
|セキュリティ|攻撃対象を減らしやすい|認証・データ処理などの対策が必要|
|JavaScript|使用可能|使用可能|
|PHP|通常は不要|使用可能だが必須ではない|
|代表的な用途|ポートフォリオ・紹介サイト|SNS・予約サイト・ECサイト|

> [!IMPORTANT] 重要  
> 「静的サイト＝動かないサイト」「動的サイト＝アニメーションがあるサイト」という意味ではない。
> 
> 静的サイトでもJavaScriptを使用すれば、アニメーションや検索機能などを実装できる。

---

## 2. Webサイトを構成する3つの要素

静的サイトと動的サイトの違いを理解するためには、**ブラウザ・Webサーバー・データベース**の役割を理解する必要がある。

|要素|役割|例え|
|---|---|---|
|ブラウザ|Webページを受信して表示する|お客さん|
|Webサーバー|リクエストに応じてデータを返す|受付スタッフ|
|データベース|情報を整理・保存する|情報を保管する倉庫|

### ブラウザ

Chrome、Safari、Edgeなど、Webサイトを閲覧するためのソフトウェアである。

HTML・CSS・JavaScriptなどを読み込み、Webページを表示する。

### Webサーバー

ブラウザから送られたリクエストを受け取り、HTMLや画像などのデータを返す。

動的サイトでは、アプリケーションプログラムと連携して情報を処理する場合もある。

### データベース

ユーザー情報、商品情報、予約情報などを整理して保存する仕組みである。

例えば、ホテルの予約サイトでは以下の情報が保存される。

- 宿泊者情報
    
- 予約日時
    
- 客室の空室状況
    
- 宿泊料金
    
- 予約履歴
    

ただし、動的サイトだからといってデータベースが必須というわけではない。

## 3. 静的サイトの仕組み

**静的サイトとは、あらかじめ生成されたHTMLなどのファイルを、そのままブラウザへ配信するWebサイトである。**

### 処理の流れ

```
sequenceDiagram
    participant B as ブラウザ
    participant S as Webサーバー

    B->>S: ① ページをリクエスト
    Note over S: 保存済みファイルを取得
    S-->>B: ② HTMLを返す
    B->>S: ③ CSS・画像・JavaScriptを要求
    S-->>B: ④ 必要なファイルを返す
    Note over B: ⑤ Webページを表示
```

※実際のファイル取得順序やリクエスト数は、ページの構成によって異なる。

### 特徴

- HTMLをアクセス時に生成する必要がない
    
- データベースなしでも構築できる
    
- CDNを利用して高速に配信しやすい
    
- サーバー側の処理が少なく、比較的シンプルな構成にできる
    

### 具体例：写真ギャラリー

100枚の写真を掲載したポートフォリオサイトを考える。

利用者が「Portrait」というタグをクリックすると、JavaScriptが写真の一覧を絞り込み、該当する作品だけを表示する。

この処理がブラウザ内で完結するのであれば、静的サイトとして実装できる。

### 例え：作り置きのお弁当

静的サイトは、**事前に完成させたお弁当を注文に応じて渡す仕組み**に似ている。

注文を受けてから料理を作る必要がないため、素早く提供できる。

---

## 4. 動的サイトの仕組み

**動的サイトとは、アクセス時の条件や利用者の情報に応じて、サーバー側でコンテンツを生成するWebサイトである。**

### 処理の流れ

```
sequenceDiagram
    participant B as ブラウザ
    participant S as Webサーバー
    participant P as PHPなどのプログラム
    participant D as データベース

    B->>S: ① 空室情報をリクエスト
    S->>P: ② 検索処理を実行
    P->>D: ③ 空室情報を問い合わせ
    D-->>P: ④ 検索結果を返す
    P-->>S: ⑤ 検索結果からページを生成
    S-->>B: ⑥ HTMLを返す
    Note over B: ⑦ 空室情報を表示
```

この例ではPHPを使用しているが、PythonやJavaScriptなどでも同様の仕組みを構築できる。

また、HTMLではなくJSONなどのデータを返し、ブラウザ側のJavaScriptが画面を更新する方式も存在する。

### 特徴

- アクセス時にサーバー側で情報を処理できる
    
- 利用者ごとに異なる情報を表示できる
    
- データベースと連携しやすい
    
- ログイン、検索、予約などの機能を実装できる
    
- サーバー側の処理が複雑になる場合がある
    

### 具体例：ホテルの予約サイト

宿泊者が10月30日の空室を検索した場合、次の処理が実行される。

1. ブラウザから検索条件を送信する。
    
2. サーバーが条件を受け取る。
    
3. プログラムがデータベースを検索する。
    
4. データベースから空室情報を取得する。
    
5. 検索結果に応じたページを生成する。
    
6. ブラウザに検索結果を表示する。
    

このように、検索条件によって表示される情報が変化する。

### 例え：注文を受けてから調理するレストラン

動的サイトは、**注文を受けてから料理を作るレストラン**に似ている。

注文内容に応じて調理するため、利用者ごとに異なる料理を提供できる。

## 5. 静的サイトでも画面を動かせる理由

静的サイトでもJavaScriptを使えば、さまざまな機能を実装できる。

例えば、次のような機能である。

- 画像の拡大表示
    
- スライドショー
    
- スクロールアニメーション
    
- タグ検索
    
- ハンバーガーメニュー
    
- ダークモード
    

これらの処理は、ブラウザ内で完結させることが可能である。

```
flowchart TD
    A["静的HTMLを読み込む"] --> B["ブラウザにページを表示"]
    B --> C["利用者がボタンをクリック"]
    C --> D["JavaScriptが処理"]
    D --> E["画面の表示を変更"]
```

重要なのは、**画面の動きと、サーバー側でのページ生成は別の概念**という点である。

---

## 6. 静的サイトと動的機能は組み合わせられる

現代のWebサイトでは、静的サイトと動的処理を組み合わせた構成も一般的である。

例えば、HTMLやCSSは事前に生成しておき、必要な情報だけをAPI経由で取得する方法がある。

```
flowchart TD
    A["ブラウザ"] -->|HTML・CSSを要求| B["静的ファイル配信サーバー"]
    B -->|ファイルを返す| A

    A -->|APIにデータを要求| C["バックエンド"]
    C -->|必要に応じて問い合わせ| D[("データベース")]
    D -->|検索結果| C
    C -->|JSONなどを返す| A

    A --> E["JavaScriptが画面を更新"]
```

この構成では、ページの土台は静的に配信される一方、必要な情報はサーバーから動的に取得される。

そのため、Webサイト全体を単純に静的・動的のどちらか一方へ分類することが難しい場合もある。

### Cloudflare Workersの場合

Cloudflare Workersでは、JavaScriptやTypeScriptなどを使ってサーバー側の処理を実行できる。

例えば、以下のような構成を実現できる。

|機能|実装方法|
|---|---|
|写真ギャラリー|静的HTML・CSS|
|タグによる写真検索|ブラウザ側JavaScript|
|アニメーション|CSS・JavaScript|
|APIから情報を取得|Cloudflare Workers|
|データベースへのアクセス|WorkersとCloudflare D1などの連携|

つまり、**PHPを使わなくても、動的な処理を備えたWebサイトを構築できる。**

## 7. よくある誤解

### Q. JavaScriptを使用すると動的サイトになる？

必ずしもならない。

ブラウザ上でアニメーションや画面の切り替えを行うだけであれば、静的サイトでも実現できる。

### Q. 動的サイトには必ずデータベースが必要？

不要である。

サーバー側のプログラムだけで処理を行い、ページを生成することもできる。

### Q. 静的サイトのほうが必ず高速？

必ずしもそうではない。

静的サイトは高速に配信しやすい構造だが、画像の容量やJavaScriptの処理量などによって表示速度は変化する。

また、動的サイトでもキャッシュを適切に使用すれば高速な配信が可能である。

### Q. 動的サイトはPHPで作るもの？

PHPは選択肢の1つにすぎない。

JavaScript、Python、Ruby、Javaなど、さまざまな言語で動的サイトを構築できる。

## 8. まとめ
![[Pasted image 20261029062204.png]]

静的サイトと動的サイトの本質的な違いは、ページを生成するタイミングと、サーバー側で実行する処理にある。

|種類|覚え方|
|---|---|
|**静的サイト**|作っておいたページをそのまま渡す|
|**動的サイト**|リクエストに応じてサーバー側でページを作る|
|**静的＋動的の組み合わせ**|ページの土台は事前生成し、必要な情報だけ取得する|

> [!SUMMARY] 最重要ポイント  
> 静的サイトと動的サイトの違いは、アニメーションの有無ではない。
> 
> **Webページを事前に生成して配信するか、アクセスに応じてサーバー側で生成するかが基本的な区別である。**
> 
> また、現代のWebサイトでは両方の仕組みを組み合わせることも一般的である。
