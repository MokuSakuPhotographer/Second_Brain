# Ciel チャット・ワードトリガー一覧

確認日：2026-10-11（日本時間）。対象：現在の通常起動先 `ai_pet_brain.py`、Dashboardチャット、指定Discordチャンネル、および常駐ランチャー。LM Studio専用運用に合わせた管理コマンド統一後のソースを基準にしています。

管理コマンドの変更は、Ciel Coreと常駐ランチャーの両方を再起動すると反映されます。この資料の認識例は副作用のない解析・モックで確認しています。実際の再起動、音声、家電、メインPC操作の成功を保証する実機テストは実施していません。

固定語句は全件、数値・方向・敬語などの組合せは構文として記載しています。LLMが通常会話として解釈する無数の言い回しは固定トリガーに含めていません。

## 送信時の共通ルール

- 管理操作・カメラの首振り・家電操作は、本文全体が命令の形に一致する必要があります。引用、説明文、否定文、裸の操作名に続く疑問符は操作しません。例：`再起動？`、`「停止して」`、`エアコンを消さないで`。
- 全体一致の自然文コマンドはNFKCで全角英数字を正規化し、英字の大小と空白を吸収します。先頭の `シエル` / `Ciel`、末尾の `、。!.,` は使えます。`再起動してくれる？` のような対応済みの明示的な依頼は認識します。
- 「部分一致」と記載したトリガーは、普通の文章や否定・引用の中でも反応する場合があります。全コマンド共通の否定・引用除外ではありません。
- 画像を添付した投稿では管理操作・予定確認・家電・首振り・記憶操作等のショートカットを実行せず、画像への会話として処理します。
- 一度に複数の命令をまとめず、1投稿につき1操作を推奨します。最初に一致した処理が使われます。
- Discordは設定済みの会話チャンネルのみ受け付けます。停止・再起動・メインPC操作は許可ユーザーに限定します。停止中ランチャーの起動・停止も同じ許可ユーザー設定を使います。Dashboardはローカルの既存アクセス設定に従います。

## 1. 本体の管理（Dashboard / Discord 共通）

| 操作 | 固定語句・構文 | 送信例と動作 |
| --- | --- | --- |
| 状態確認 | `システム状態` / `状態` / `本体状態` / `状態確認` / `status` | `本体状態`：稼働中は本体が稼働中と回答。停止中はランチャー待機状態を回答。 |
| 起動 | `起動` / `start` / `boot` / `立ち上げて` / `立ち上がって` | `起動して`：停止中は常駐ランチャーが本体を起動。稼働中は起動済みと回答。 |
| 再起動 | `再起動` / `restart` / `reboot` | `シエル、再起動してくれる？`：Coreを安全に再起動。停止中は起動として処理。 |
| 停止 | `停止` / `終了` / `shutdown` / `stop` / `exit` / `落として` | `本体を停止してください。`：Coreを安全停止。ランチャーは待機を続ける。Windowsのシャットダウンではありません。 |

起動・再起動・停止の構文：先頭に `本体` / `システム` / `プログラム` と任意の `を` を付けられます。動詞名だけ、動詞名＋`して`、動詞名＋`して`＋敬語、動詞名＋`お願いします` が対応形です。敬語は `ください` / `下さい` / `くれる` / `ほしい` / `お願い` / `お願いします`。`落として`・`立ち上げて`・`立ち上がって` には敬語を直接続けます。

両チャットとも、本体停止中の起動・状態確認には常駐ランチャーが必要です。停止中のDashboardに送られた他の投稿は未実行として返答し、次の起動後に機器操作を再実行しません。Ollama管理コマンドは両チャットの受付対象から外しました。LM Studioそのものの起動・停止を行うチャットコマンドはありません。

## 2. マスター状態（Dashboard / Discord 共通）

| 送信コマンド | 意味 |
| --- | --- |
| `/STATE HOME` | 在宅 |
| `/STATE AWAY` | 外出 |
| `/STATE SLEEP` | 就寝 |
| `/STATE WORKING` | 作業中 |
| `/STATE GAMING` | ゲーム中 |
| `/STATE BUSY` | 取り込み中 |
| `/STATE IDLE` | 待機 |
| `/STATE AUTO` | 手動指定を解除して自動判定に戻す |

`/STATE` と状態名の2要素で送ります。英字大小・全角英数字を吸収します。余分な文章、句読点、第三の要素は付けません。手動指定は解除まで継続します。`/STATE SLEEP` はマスター状態の指定で、おやすみモードの定型発話シーケンスとは別です。既存のおやすみモードがONなら `/STATE AUTO` だけでは解除されないため `おはよう` を使います。状態に伴う家電操作は現状dry-runで、`/STATE AWAY` 等だけで家電を自動操作する仕様ではありません。

| 用途 | 全語句 | 動作 |
| --- | --- | --- |
| ON | `おやすみ` / `お休み` | 定型発話後、おやすみモードに移行。自律発話、カメラ巡回等を抑制。 |

全灯は標準ボタン `on-100` または登録信号、暖色は「暖色」「くつろぎ」、寒色は「寒色」「読書」の登録信号を使います。対象・信号が一意に決まらない場合は操作しません。常夜灯・調光のトリガーは未実装。API送信成功と、実際の点灯状態の確認は別です。

## 17. どのトリガーが優先されるか

- 管理コマンド（メインPC→マスター状態→本体→おやすみモード）。Discordの停止・再起動・PC操作は権限確認後に即時受付。本体停止中はランチャーが起動・停止・状態のみ処理。
- 画像添付がなければ、Google Calendar→Nature Remo→首振り→自律発話→話題疲労→長期記憶一覧→記憶無効化→日記→記憶保存→カメラ視界→名前の呼びかけ→興味一覧→ムード一覧。
- どれにも該当しなければ通常会話。必要なObsidian参照・内部記憶参照・感情等の評価を行う。
